Guia de Uso — IA Command

Configure e opere o IA Command: provedor de IA, conexão com ERP Protheus, canais WhatsApp, módulos de conhecimento, intenções, sinônimos, diálogos, pipeline Text-to-SQL dinâmico e auditoria completa. Leia em ordem pelas fases para um setup correto e sem retrabalho.

1

Visão Geral

Entenda a arquitetura antes de configurar

1.1O que é o IA Command⌄

O IA Command transforma o ERP Protheus em uma conversa. O usuário envia perguntas livres pelo WhatsApp — "faturamento de abril por produto", "top clientes do trimestre", "contas a pagar vencidas" — e o sistema interpreta, consulta o ERP e responde em linguagem natural.

IA como provider primário
Todo pedido passa primeiro por um modelo de linguagem externo (Groq, OpenAI, Gemini, DeepSeek ou Claude Anthropic). O motor local existe apenas como último recurso quando não há chave ou a IA está indisponível.
Dois modos de consulta ERP
Datasets cadastrados: SQL fixo parametrizado para intenções simples registradas manualmente. Text-to-SQL dinâmico: a IA gera o SQL em tempo real para compras, faturamento, financeiro e comissão com base no esquema real do Protheus (SX2/SX3).
Multi-turn conversacional
Contexto mantido por 10 minutos por usuário/empresa. Perguntas de refinamento ("só o mês passado", "agora por vendedor", "filtra cliente Acme") herdam automaticamente módulo, período e filtros do turno anterior.
Isolamento por empresa
Conexões ERP, chaves de IA, módulos, datasets, intenções, sinônimos e diálogos são configurados independentemente por empresa. Um usuário só acessa dados da empresa selecionada.
ℹTagline: "Seu ERP conversando com você." O usuário pergunta em português livre; o IA Command cuida de toda a tradução para dados do Protheus.
1.2Arquitetura IA-first — visão em camadas⌄

A diretriz é IA-first: a inteligência artificial externa é o provider principal para qualquer pedido. Guardrails determinísticos corrigem o contrato da IA quando necessário. O motor local resolve apenas como último recurso.

Diagrama 1 — Camadas da Arquitetura IA Command
⚠IA-first é a diretriz central. O resolver local nunca deve ser a estratégia principal. Toda nova regra de negócio vai nos guardrails ou sinônimos — nunca no resolver local.
1.3Motor de Classificação — Cascata de decisão⌄

Para cada mensagem recebida, o sistema percorre uma cascata antes de chegar ao ERP. Entender esse fluxo é essencial para diagnosticar comportamentos inesperados.

Diagrama 2 — Cascata de Classificação
Bypass dinâmico (sem chave)
Quando não há chave de IA e a mensagem tem escopo claro e não ambíguo, o sistema cria a intenção diretamente sem chamar IA. Só resolve casos simples — mensagens complexas retornam orientação ao usuário.
Guardrails sobrescrevem a IA
Regras determinísticas são aplicadas após o contrato IA. Ex: "contas a pagar" → financeiro/pagar; "saldo bancário" → financeiro; período genérico (mes_atual) é substituído pelo período do contexto anterior.
Fallback de chave global
Se a empresa não tem chave própria, o sistema usa qualquer chave de IA disponível no banco de dados. O sistema funciona mesmo sem configuração específica por empresa.
1.4Multi-turn e Contexto Conversacional⌄

O sistema mantém contexto de conversa por usuário/empresa com TTL de 10 minutos. Perguntas de refinamento herdam automaticamente módulo, período, filtros e entidades já resolvidas no turno anterior.

Diagrama 3 — Herança de contexto multi-turn
O que é herdado automaticamente
Módulo ERP, período (se não genérico), filtros de entidade já resolvidos (cliente, produto, vendedor, fornecedor), carteira, estado do título, fluxo tipo e nível de contexto.
Comparação mensal/anual vira agrupamento
"Comparação mensal" → agrupar_por: mes; "comparação anual" → agrupar_por: ano. Permite drilldowns temporais sem mudar o filtro de período.

2.4Middleware Protheus — Segurança e controle SQL⌄

O Middleware Protheus é a camada de segurança aplicada sobre todo SQL gerado pela IA (Text-to-SQL dinâmico). Ele bloqueia operações destrutivas, injeta filtros de tenant e limita o número de linhas retornadas.

config-middleware-protheus.html — Configuração do Middleware
Ativado
500
Ativado (filial)
INSERT, UPDATE, DELETE, DROP, CREATE, ALTER, TRUNCATE
Bloqueio DDL/DML crítico
Impede que qualquer SQL gerado pela IA execute INSERT, UPDATE, DELETE, DROP, CREATE, ALTER ou TRUNCATE. Qualquer tentativa é bloqueada antes de chegar ao banco. Nunca desative.
SET ROWCOUNT
Limita o número de linhas retornadas por consulta (padrão: 500). Evita que queries sem filtro adequado travem o banco ou retornem volumes inviáveis para a resposta WhatsApp.
Filtro de tenant (LOBO_GUARA)
Injeta automaticamente o filtro de filial/empresa em todas as queries. Garante que um usuário de uma empresa não veja dados de outra filial no mesmo banco Protheus.
Validação SX3 (aviso apenas)
Campos usados no SQL gerado pela IA são verificados contra o dicionário SX3. Campos não encontrados geram apenas um aviso nos logs — nunca bloqueiam a execução. Diretriz IA-first: a IA tem prioridade sobre o dicionário.
!Nunca desative o bloqueio DDL/DML. O SQL é gerado por IA e pode conter instruções destrutivas por erro de interpretação ou prompt injection via WhatsApp.

O Monitor exibe o estado de cada sessão WhatsApp conectada. Mostra QR Code para autenticação, status de conexão (conectado, desconectado, aguardando QR), bateria e mensagens em fila. É o ponto de controle operacional diário.

Quando o canal está desconectado, o Monitor exibe o QR Code para escanear com o WhatsApp do número configurado. Após autenticação, o status muda para "Conectado" automaticamente.

4.2Datasets — SQL base por intenção⌄

Um dataset é um SQL fixo parametrizado que o sistema executa quando a intenção correspondente é identificada. Diferente do Text-to-SQL dinâmico, o SQL do dataset é escrito manualmente pelo administrador e não muda. Use para consultas simples, estáveis e de alto volume.

Nome obrigatório
Identificador interno. Usado para vincular o dataset a intenções específicas.
SQL Base obrigatório
Query parametrizada com placeholders :PARAM_NOME. Os parâmetros mais usados são :DATA_INI, :DATA_FIM, :EMPRESA, :FILIAL, :CLIENTE, :PRODUTO. O sistema substitui os parâmetros com os valores extraídos da intenção.
Conexão ERP
Qual conexão de banco executar. Se não informado, herda a conexão do módulo pai.
Modo de resposta
Como formatar o resultado: tabela (lista com colunas), total (soma de um campo), ranking (top N), comparativo (período atual vs anterior). Informa o formatador de resposta.
Limite de linhas
Máximo de linhas a retornar. Para respostas WhatsApp, mantenha abaixo de 20. Para relatórios, pode ser maior (o middleware ainda aplica o ROWCOUNT global).

4.5Diálogos — Respostas conversacionais⌄

Diálogos são respostas fixas para mensagens que não são consultas ao ERP — saudações, perguntas sobre o sistema, comandos de ajuda. Evitam que mensagens como "oi", "bom dia" ou "o que você faz?" gerem erros de classificação.

Normalizações definem transformações aplicadas ao texto da mensagem antes da classificação. Permitem corrigir abreviações, remover palavras desnecessárias, padronizar grafias e expandir acrônimos — tornando a mensagem mais clara para a IA interpretar.

5

Text-to-SQL Dinâmico

A IA gera SQL em tempo real com base no esquema real do Protheus

5.1Pipeline Text-to-SQL — 8 passos⌄

Quando uma intenção dinâmica é identificada (compras, faturamento, financeiro ou comissão), o sistema executa um pipeline de 8 passos para gerar, validar e executar o SQL no Protheus. Cada passo é logado para diagnóstico.

Diagrama 4 — Pipeline Text-to-SQL Dinâmico (8 passos)
Passo 1 — Contrato Temporal
Combina resolução determinística de período (DATA_INI, DATA_FIM) com sugestão da IA. Confiança mínima para aceitar sugestão IA: 0,80.
Passo 2 — Query Plan
A IA interpreta o que o usuário quer: quais tabelas, colunas, joins, agregações e ordenações usar. Resultado: um plano JSON estruturado.
Passo 3 — Resolução de entidades
Busca no Protheus o código real da entidade mencionada. "Acme" → busca em SA1 pelo nome, retorna código. Tolerância a erros de digitação: termos curtos usam busca por prefixo (5 chars).
Passo 4 — Geração de SQL pela IA
A IA gera o SQL final com base no query plan, entidades resolvidas, esquema SX2/SX3 e regras do módulo. O prompt inclui as tabelas reais do Protheus.
Passo 5 — Validação SX3 (aviso)
Verifica se os campos do SQL existem no dicionário SX3. Campos não encontrados geram log "Aviso SX3 ignorado por diretriz IA-first" — a execução continua normalmente.
Passo 6 — Middleware SQL
Bloqueia DDL/DML, injeta filtro de tenant (filial), aplica SET ROWCOUNT. Se bloqueado, retorna erro sem executar nada no banco.
Passo 7 — Execução ERP
SQL final executado na conexão Protheus configurada. Resultado retornado como array de objetos.
Passo 8 — Formatação IA
Para resultados simples (<50 linhas, sem group_by composto), a IA formata a resposta em linguagem natural. Para grandes volumes, o formatador local é usado.

Checklist de Implantação

Ordem recomendada e diagnóstico de problemas comuns

7.1Ordem recomendada de configuração⌄

Siga esta sequência para evitar retrabalho. Cada etapa depende da anterior estar funcionando.

1
Configurar IA (config-ia.html) — Informe o provedor e a chave de API. Teste a conexão. Sem isso, apenas bypass funciona.
2
Configurar Conexão ERP (config-conexoes.html) — Adicione a conexão ao banco Protheus. Teste a conectividade com o botão de teste.
3
Configurar Middleware (config-middleware-protheus.html) — Revise o ROWCOUNT máximo e confirme que o bloqueio DDL/DML está ativo.
4
Cadastrar Canal WhatsApp (admin-canais-whatsapp.html) — Adicione o número do canal e vincule à empresa.
5
Autenticar no Monitor (monitor.html) — Escaneie o QR Code com o celular do número configurado.
6
Configurar Números Autorizados (admin-numeros-whatsapp.html) — Adicione os números que podem fazer consultas. Deixe vazio para aceitar qualquer número (somente em testes).
7
Testar módulos dinâmicos — Envie uma pergunta de teste pelo WhatsApp: "faturamento do mês". Verifique em Execuções se a intenção foi classificada corretamente.
8
Consultar SX2/SX3 (admin-protheus-sx2/sx3.html) — Verifique quais tabelas e campos estão disponíveis para confirmar que o Text-to-SQL tem acesso ao esquema correto.
9
Adicionar Sinônimos (admin-sinonimos.html) — Após os primeiros dias de uso, identifique termos não reconhecidos no histórico de mensagens e adicione-os.
10
Configurar Diálogos (admin-dialogos.html) — Adicione respostas para saudações e perguntas sobre o sistema que não sejam consultas ERP.
11
Criar Datasets manuais (admin-datasets.html) — Para consultas frequentes e estáveis que não precisam de Text-to-SQL, crie datasets com SQL fixo parametrizado.
12
Monitorar Auditoria e Logs — Revise execuções, interpretações e log de consultas periodicamente para identificar oportunidades de melhoria.
✓Os módulos compras_dinamico, faturamento_dinamico, financeiro_dinamico e comissao_dinamico são criados automaticamente na inicialização do sistema — não é necessário cadastrá-los.
