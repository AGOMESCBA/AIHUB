Como funciona o SE API Configurador

O SE API Configurador permite integrar seu sistema ao SoftExpert através de chamadas SOAP/XML configuradas visualmente — sem precisar escrever código. Você define os templates XML uma vez, e as configurações mapeiam os dados do seu sistema para os campos do SE.

Há 4 conceitos principais: Template (estrutura XML), Configuração (endpoint + autenticação + mapeamentos), Flow (sequência de chamadas) e Histórico (log de execuções).

Modos de template: Campos Fixos vs. {{form_fields}}

Existem dois modos de trabalhar com os campos do formulário SoftExpert:

📌 Modo 1 — Campos Fixos no XML
Os fieldID do SE ficam escritos diretamente no XML. Você usa placeholders {{nome}} apenas para os valores.

✅ Use quando a estrutura de campos raramente muda.
🔄 Modo 2 — {{form_fields}} Dinâmico
O XML usa {{form_fields}} como marcador. O motor gera todos os blocos <item> automaticamente a partir dos mapeamentos que tiverem o Campo SE preenchido.

✅ Use quando os campos do SE podem variar por configuração.
💡
Dica: Os dois modos podem coexistir no mesmo XML. Por exemplo, {{process_id}} para o ID do processo (valor único) e {{form_fields}} para o bloco de campos do formulário.

Comparação visual:

Modo 1 — Fixo no XML
<formFields> <item> <fieldID>CANDIDATE_NAME</fieldID> <fieldValue>{{nome}}</fieldValue> </item> <item> <fieldID>CANDIDATE_EMAIL</fieldID> <fieldValue>{{email}}</fieldValue> </item> </formFields>
Modo 2 — Dinâmico
<formFields> {{form_fields}} <!-- Motor gera os <item> automaticamente --> </formFields> <!-- Resultado gerado: <item> <fieldID>CANDIDATE_NAME</fieldID> <fieldValue>João</fieldValue> </item> ... -->
Passo 1 — Criar um Template XML

O Template define a estrutura fixa do XML que o SoftExpert espera receber. É compartilhado entre todas as empresas e pode ser reutilizado em múltiplas configurações.

1
Obtenha o XML esperado pelo SoftExpert
Consulte a documentação da API do SE ou use o XML de uma chamada SOAP que já funciona. Esse será o "esqueleto" do template.
2
Substitua os valores dinâmicos por placeholders
Onde o XML teria um valor real (nome, ID, etc.), coloque {{nome_do_placeholder}}. Use nomes em minúsculas com underscore.
3
Escolha o Tipo do template
START → Iniciar um processo no SE  |  DATA → Inserir dados em um formulário  |  MOVE → Avançar uma atividade do workflow
4
Cole o XML e salve
O sistema extrai automaticamente todos os placeholders detectados e os exibe como chips abaixo do campo XML.

Exemplo de template START com {{form_fields}}:

<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/"> <soapenv:Body> <ws:startProcess> <processID>{{process_id}}</processID> <formFields> {{form_fields}} </formFields> </ws:startProcess> </soapenv:Body> </soapenv:Envelope> <!-- Placeholders detectados: process_id, form_fields -->
⚠️
Atenção: O nome form_fields é reservado pelo motor. Ao usá-lo, o sistema gera automaticamente os blocos <item> a partir dos mapeamentos com "Campo SE" preenchido. Não use esse nome para outro fim.

Passo 3 — Configurar os Mapeamentos

Os mapeamentos conectam os dados do seu sistema aos campos do SoftExpert. Cada linha de mapeamento tem até 4 informações:

ColunaO que éQuando preencherExemplo
Campo Origem
source_field		 Nome do campo do seu sistema que será enviado na execução Sempre nome, email, vaga_id
Campo SE
se_field_id		 Código do campo no formulário do SoftExpert Quando usar {{form_fields}} no template CANDIDATE_NAME, JOB_TITLE
Placeholder Nome do {{placeholder}} que está no XML do template Quando o campo aparece individualmente no XML process_id, token
Valor Padrão Valor usado quando o campo de origem vier vazio ou ausente Opcional — para campos opcionais PS-2024, ativo

Exemplo de mapeamento completo:

Campo Origem (nosso sistema)Campo SE (SoftExpert)Placeholder XMLValor Padrão
nomeCANDIDATE_NAME——
emailCANDIDATE_EMAIL——
telefoneCANDIDATE_PHONE——
vaga_tituloJOB_TITLE——
se_process_id—process_idPS-001
ℹ️
Como o motor processa: As 4 primeiras linhas (com Campo SE preenchido) são usadas para gerar os blocos <item> dentro de {{form_fields}}. A última linha (com Placeholder) é usada para substituir {{process_id}} diretamente no XML.

XML gerado automaticamente pelo motor:

<soapenv:Envelope> <soapenv:Body> <ws:startProcess> <processID>PS-001</processID> <!-- de {{process_id}} --> <formFields> <!-- gerado de {{form_fields}} --> <item> <fieldID>CANDIDATE_NAME</fieldID> <fieldValue>João Silva</fieldValue> </item> <item> <fieldID>CANDIDATE_EMAIL</fieldID> <fieldValue>joao@email.com</fieldValue> </item> <item> <fieldID>JOB_TITLE</fieldID> <fieldValue>Analista de RH</fieldValue> </item> </formFields> </ws:startProcess> </soapenv:Body> </soapenv:Envelope>

Passo 4 — Criar um Flow (opcional)

Um Flow encadeia múltiplas Configurações em sequência. Útil quando o processo completo exige várias chamadas ao SE — por exemplo: iniciar processo → inserir dados → avançar atividade.

1
Crie as Configurações individuais primeiro
Cada step do flow é uma Configuração. Certifique-se de que cada uma está correta antes de montar o flow.
2
Adicione os steps na ordem correta
Use ▲ e ▼ para reordenar. O motor executa do step 1 ao último em sequência, passando os mesmos dados de entrada para todos.
3
Configure "Parar em erro"
Se marcado, o flow interrompe nos steps seguintes caso este step falhe. Se desmarcado, continua mesmo com erro.
ℹ️
Os dados de entrada são compartilhados entre todos os steps do flow. O campo source_field de cada mapeamento é buscado no mesmo objeto JSON enviado na execução.
Passo 5 — Executar e monitorar

Clique em ▶ Executar em qualquer Configuração ou Flow para fazer uma chamada de teste. Informe os dados de entrada em JSON:

// Dados de entrada para o exemplo anterior: { "nome": "João Silva", "email": "joao@empresa.com", "telefone": "(65) 99999-0000", "vaga_titulo": "Analista de RH", "se_process_id":"PS-2024-001" }

Todas as execuções ficam registradas na aba Histórico com o XML enviado, a resposta do SE, o status HTTP e o tempo de resposta. Use o agrupamento por coluna para analisar padrões de erro.
